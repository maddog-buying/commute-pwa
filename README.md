# 上下班路線

石碇服務區與國票金控之間，比較三條路線現在的預估時間。上班與下班方向分開定義（`routes.js` 的 `MODES`）。純 HTML/JS，沒有 build。

## 部署資料中繼（Apps Script）

開放資料不允許網頁跨網域讀取，所以要一支 Apps Script 代抓。Google 的主機連不上高公局的 `tisvcloud`，國道資料改走交通部 TDX，需要自己的金鑰。

1. 到 https://script.google.com 建立新專案，把 `backend/Code.gs` 全部貼上。
2. 專案設定 → 指令碼屬性，新增 `TDX_CLIENT_ID` 與 `TDX_CLIENT_SECRET`。金鑰不要寫進程式碼，這個 repo 是公開的。
3. 部署 → 新增部署作業 → 類型選「網頁應用程式」。執行身分選「我」，存取權選「所有人」。
4. 開 `/exec?diag=1` 確認金鑰與 TDX 路徑可用。
5. 把 `/exec` 網址填進 `config.js`，並把 `sw.js` 的 `CACHE` 版本 +1。

改了 `Code.gs` 之後要到「管理部署作業 → 編輯 → 新版本」才會生效。

## 本機預覽

launch config `commute-pwa`（port 8091）。

- `?demo`：虛構的塞車情境，看畫面用。
- `?dev`：在瀏覽器裡跑真正的 `backend/Code.gs`，資料是即時的。

## 分析怎麼算

每段路的時間加總，來源分三種：

| 路段 | 來源 |
|---|---|
| 國五、國三 | 高公局路段旅行時間（經 TDX） |
| 南港聯絡道、國五接國三匝道 | 高公局車輛偵測器（經 TDX） |
| 環東、堤頂大道、研究院路 | 臺北市交控中心路段車速（約 5 分鐘） |
| 文山路、北深路、深南路、南深路、經貿二路 | 沒有公開即時資料，用 `routes.js` 裡的估算車速 |

路線與估算車速都在 `routes.js`。實際開幾次後，可以照實際時間調整 `est`（離峰、尖峰）與 `delay`（號誌秒數）。

臺北市的 `GetVD.xml` 停在 2024 年，要用 `GetVD.xml.gz`。任何來源超過 30 分鐘沒更新就不採用。

## 即時定位與自動更新

按下開始後持續定位，每 60 秒重新抓路況。位置只在手機上計算，不會送到後端。

- `routes-geometry.js` 是各路段的座標，由 `tools/build_geometry.py` 產生，路線改變時要重跑。路段順序必須和 `routes.js` 的 `segments` 一致。
- `tracking.js` 把 GPS 位置對應到路段，只計算剩餘路程。離開某條路線超過 30 秒就算錯過，不再參與比較。
- 新路線要快 60 秒以上才換推薦。讀取失敗的來源暫用上一筆。
- 不在前景時不呼叫 API，抵達或連續 2 小時後自動停止。TDX 基礎會員約每分鐘 5 次，每次分析用 3 次。
- 手機螢幕關閉或切到其他 App 時，瀏覽器會暫停定位與更新，所以分析中會要求螢幕保持亮著。
